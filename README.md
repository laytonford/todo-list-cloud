# COSC349 Assignment 2

## To-Do List Overview

This project is a cloud-based simple to-do list application developed for COSC349

Users can:

- View tasks
- Add tasks
- Mark tasks as complete or incomplete
- Delete tasks

The application uses AWS services and follows this request path:

**Browser -> S3 Website -> Lambda Function -> S3 Data Storage**

The frontend is hosted using an S3 static website bucket. Application logic is handled by an AWS Lambda function, which stores and retrieves task data from a separate private S3 bucket

## Tools

The project uses:

- AWS S3 – hosts the frontend and stores task data
- AWS Lambda – handles application logic and API requests
- AWS CloudFormation – creates and configures the cloud resources
- AWS Lambda Function URL – provides the API endpoint
- AWS CLI – packages, deploys, verifies and removes the application
- Python – used by the Lambda function and deployment scripts
- Git – version control

The deployment uses the AWS Academy Learner Lab environment in the `us-east-1` region. The AWS Academy `LabRole` is used by Lambda because the Learner Lab does not allow the creation of a new IAM role

## Deployment

Make sure you have installed:

- Git
- AWS CLI
- Python 3
- Git Bash

The project was developed using:

- Git (ver. 2.55.0.windows.5)
- AWS CLI (ver. 2.37.9)
- Python (ver. 3.14.6)
- AWS Lambda Python runtime (3.12)

Before deploying, you will need to manually start the AWS Academy Learner Lab

In the Learner Lab, open the AWS details/credentials section and copy the provided AWS CLI credentials into your AWS CLI credentials file:

    ~/.aws/credentials

The AWS CLI must be configured with active AWS Academy credentials before deploying

Clone the repository and enter the project directory:

    git clone https://github.com/laytonford/todo-list-cloud
    cd todo-list-cloud

Deploy the system with:

    ./scripts/deploy.sh

The deployment script:

1. Creates an S3 bucket for CloudFormation deployment artifacts
2. Generates a random API token
3. Packages the CloudFormation template
4. Creates the S3 buckets and Lambda function
5. Creates the Lambda Function URL
6. Generates the frontend configuration file
7. Uploads the frontend to the website bucket

No cloud resources need to be manually created

The deployment normally takes a few minutes

## Access

Open the app in a browser with: http://todo-list-site-672088268256.s3-website-us-east-1.amazonaws.com/

## Verification

In Bash, run:

    ./scripts/verify.sh

The script checks that the CloudFormation deployment exists and performs a complete application workflow through the cloud:

- Creates a task
- Reads the task from S3
- Marks the task as completed
- Reads the updated task
- Deletes the task

At the end of the verification process, the test data is deleted

## Removal

To remove all cloud resources created by the project, run:

    ./scripts/destroy.sh

This removes:

- The CloudFormation stack
- The Lambda function
- The Lambda Function URL
- The website S3 bucket and its contents
- The task data S3 bucket and its contents
- The CloudFormation deployment artifact bucket
- The locally generated `frontend/config.js`

The task data is not retained after destruction

## Development and Redeployment

Frontend files are located in:

    frontend/

The Lambda application logic is located in:

    lambda/api/handler.py

The CloudFormation infrastructure is located in:

    cloudformation/template.yaml

Deployment scripts are located in:

    scripts/

Changes to the frontend or Lambda code can be deployed with:

    ./scripts/deploy.sh

The deployment script automatically generates a new API token and updates the frontend configuration

A complete clean rebuild can be performed with:

    ./scripts/destroy.sh
    ./scripts/deploy.sh

The deployment can then be checked with:

    ./scripts/verify.sh

## Generated Files

The following files are generated during deployment and are not stored in Git:

    packaged.yaml
    frontend/config.js

`packaged.yaml` is generated by the CloudFormation packaging process

`frontend/config.js` contains the current API URL and deployment API token. It is generated automatically by `deploy.sh` and is excluded from Git so that the token is not committed to the repository
